## 1. Purpose

A simple food-ordering coordinator app for a hostel group. Each day, members log in and select what food they want from a set of local shops. One person (admin) collects all orders and needs a clean shopping list to take to each shop, plus a detailed view of who ordered what.

## 3. Auth design (important â€” read carefully)

Users must be able to sign up with **just a Name and a Password** â€” no visible email field. Since Firebase Auth requires an email, implement this internally:

1. On signup, normalize the name â†’ `usernameLower` (lowercase, trim, spaces removed).
2. Check `usernames/{usernameLower}` doc doesn't already exist (public read).
3. Build a synthetic email: `${usernameLower}@hostelfoods.app`
4. Call `createUserWithEmailAndPassword(auth, syntheticEmail, password)`.
5. Immediately after (now authenticated), create:
   - `usernames/{usernameLower}` â†’ `{ uid, email: syntheticEmail, createdAt }`
   - `users/{uid}` â†’ `{ name, usernameLower, isAdmin: false, createdAt }`

For login: user enters Name + Password â†’ app reads `usernames/{usernameLower}` to get the synthetic email â†’ calls `signInWithEmailAndPassword`.

Show a friendly error if the username is taken or doesn't exist / wrong password.

**First admin setup:** after first signup, the developer manually sets `isAdmin: true` on that user's doc in the Firebase console. Document this clearly in a `README.md` "Post-Deploy Setup" section.

## 4. Data model (Firestore)

```
users/{uid}
  name: string
  usernameLower: string
  isAdmin: boolean
  createdAt: timestamp

usernames/{usernameLower}
  uid: string
  email: string
  createdAt: timestamp

shops/{shopId}
  name: string
  order: number        // display order
  active: boolean

shops/{shopId}/items/{itemId}
  name: string
  price: number
  active: boolean
  updatedAt: timestamp

orders/{date}/userOrders/{uid}      // date format "YYYY-MM-DD", Asia/Colombo timezone
  userName: string                  // snapshot of name at order time
  items: [
    { shopId, shopName, itemId, itemName, price, qty }
  ]
  total: number
  createdAt: timestamp
  updatedAt: timestamp
```

Note: item `price` is copied into the order at the moment of saving. If admin changes a price later, already-saved orders keep the old price (historically accurate); the user must resave their order to pick up a new price. This is intentional â€” implement it this way.

Compute "today" client-side in `Asia/Colombo` timezone as `YYYY-MM-DD`, in a single shared util `src/utils/today.js`.

## 8. Firestore Security Rules â€” `firestore.rules`

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(uid) {
      return isSignedIn() && request.auth.uid == uid;
    }

    function isAdmin() {
      return isSignedIn() &&
        exists(/databases/$(database)/documents/users/$(request.auth.uid)) &&
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true;
    }

    match /usernames/{usernameLower} {
      allow read: if true;
      allow create: if isOwner(request.resource.data.uid);
      allow update, delete: if false;
    }

    match /users/{uid} {
      allow read: if isOwner(uid) || isAdmin();
      allow create: if isOwner(uid) && request.resource.data.isAdmin == false;
      allow update: if isOwner(uid) && request.resource.data.isAdmin == resource.data.isAdmin;
      allow update: if isAdmin();
    }

    match /shops/{shopId} {
      allow read: if true;
      allow write: if isAdmin();

      match /items/{itemId} {
        allow read: if true;
        allow write: if isAdmin();
      }
    }

    match /orders/{date}/userOrders/{uid} {
      allow read: if isOwner(uid) || isAdmin();
      allow create, update: if isOwner(uid);
      allow delete: if isOwner(uid) || isAdmin();
    }
  }
}
```
